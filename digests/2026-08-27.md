## Networking

### [Generally Available: Azure Bastion shareable link expiration](https://azure.microsoft.com/en-us/updates?id=570020)

**Status:** Launched | **Published:** 2026-08-26 | **Products:** Azure Bastion | **Tags:** Features, Security

Azure Bastion now generally supports setting expiration dates on shareable links to enhance security by limiting persistent access to resources.

- Administrators can specify date and time expiration for each shareable link when created.
- Expired links become unusable, preventing further connections to the target resource.
- Feature requires Azure Bastion Standard SKU and must be enabled in the Bastion configuration.
- Supports up to 500 shareable links per Bastion resource and 50 requests (create/delete) at a time.

Documentation: [Create a shareable link for Azure Bastion](https://learn.microsoft.com/en-us/azure/bastion/shareable-link)

### [Public Preview: IPv6 dual-stack support for Azure Bastion](https://azure.microsoft.com/en-us/updates?id=570025)

**Status:** In preview | **Published:** 2026-08-26 | **Products:** Azure Bastion | **Tags:** Features, Security

Azure Bastion now supports IPv4 and IPv6 dual-stack configurations in public preview, enabling users to connect via IPv6 while maintaining IPv4 connections to target VMs, enhancing connectivity options.

- Dual-stack support allows new Bastion deployments to have both IPv4 and IPv6 public IP addresses; existing IPv4-only deployments cannot be converted.
- IPv6 is supported only for user-to-Bastion connections; Bastion-to-VM connections remain IPv4.
- Dual-stack requires virtual networks and AzureBastionSubnet configured for IPv6 dual stack and compatible VM network interfaces.
- IPv6 is not supported on Private-only Bastion deployments or between Bastion and target VMs.

Documentation: [About Azure Bastion configuration settings](https://learn.microsoft.com/en-us/azure/bastion/configuration-settings)

### [Generally Available: Connect to AKS clusters using Azure Bastion](https://azure.microsoft.com/en-us/updates?id=570030)

**Status:** Launched | **Published:** 2026-08-26 | **Products:** Azure Bastion, Azure Kubernetes Service (AKS) | **Tags:** Features, Security

Azure Bastion now generally supports secure, seamless connections to AKS clusters, enabling safer Kubernetes management without exposing private endpoints or needing extra infrastructure.

- Enables secure tunneling from local machines to AKS cluster API servers via Azure Bastion.
- Eliminates the need for jump boxes, VPNs, or additional access agents by using native client tunneling.
- Requires Standard or Premium Bastion SKU with native client support and appropriate network permissions.
- Improves security posture by avoiding public exposure of private AKS cluster endpoints while maintaining standard Kubernetes tool usage.

Documentation: [Connect to AKS Private Cluster Using Azure Bastion - Azure Bastion](https://learn.microsoft.com/en-us/azure/bastion/bastion-connect-to-aks-private-cluster)
