## Hybrid + multicloud

### [Public Preview: Azure Multicloud Interconnect](https://azure.microsoft.com/en-us/updates?id=570364)

**Status:** In preview | **Published:** 2026-08-31 | **Products:** Azure ExpressRoute | **Tags:** Services

Azure Multicloud Interconnect is now in public preview, offering managed private connectivity between Azure and supported cloud providers like AWS to simplify and secure multicloud deployments.

- Provides private, high-throughput cloud-to-cloud connectivity using Azure ExpressRoute as the foundation.
- Simplifies deployment with a guided onboarding experience and automated provisioning via activation keys.
- Built-in resiliency with redundant infrastructure and MACsec-enabled physical links ensures high availability for mission-critical workloads.
- Currently supports Amazon Web Services (AWS) as the first cloud provider in preview, enabling seamless connection of Azure VNets with AWS VPCs.

Documentation: [What is Azure Multicloud Interconnect Preview?](https://learn.microsoft.com/en-us/azure/multicloud-interconnect/overview)

## Storage

### [Public Preview: Per-disk resiliency for Azure VMs](https://azure.microsoft.com/en-us/updates?id=569711)

**Status:** In preview | **Published:** 2026-08-31 | **Products:** Azure Disk Storage | **Tags:** Feature

Azure introduces per-disk resiliency in public preview, allowing VMs to continue running when individual data disks lose connectivity, improving application availability without requiring VM restarts.

- Per-disk resiliency detaches only the affected data disk during connectivity issues, keeping the VM and other disks operational.
- Currently in public preview in select regions and must be enabled per managed data disk; OS disks retain default VM restart behavior.
- Ideal for workloads where a single data disk failure should not impact the entire VM, such as clustered apps, containerized workloads, and backup disks.
- Limitations include unsupported VMs created before August 15, 2026, no support for Write Accelerator VMs, and the setting is not preserved by VM restore or backup operations.

Documentation: [Improve workload availability with per-disk resiliency (preview) - Azure Virtual Machines](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-per-disk-resiliency)
