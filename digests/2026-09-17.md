### [Public Preview: Azure SQL updates for mid-September 2026](https://azure.microsoft.com/en-us/updates?id=571056)

**Status:** In preview | **Published:** 2026-09-16 | **Products:** Azure SQL Database | **Tags:** Feature

Azure SQL now supports configurable soft delete for logical servers, enabling self-restore within a retention period to prevent accidental data loss without Microsoft support.

- Soft delete can be configured for Azure SQL logical servers with retention periods from 1 to 7 days, allowing recovery of deleted servers and their databases.
- This feature improves operational safety by reducing risks during automation, scripted cleanup, or bulk operations.
- Soft delete retention can be set or updated via PowerShell, Azure CLI, or Azure portal (for existing servers), but not during server creation in the portal.
- Customers gain enhanced governance and protection by adding a recovery buffer to mitigate irreversible loss due to human error.

Documentation: [Restore a Deleted Logical Server (Preview) - Azure SQL Database](https://learn.microsoft.com/en-us/azure/azure-sql/database/deleted-logical-server-restore?view=azuresql&tabs=azure-portal)

### [Retirement Update: SAP container images removed October 14, 2026](https://azure.microsoft.com/en-us/updates?id=571342)

**Status:** Retirement | **Published:** 2026-09-16 | **Tags:** Retirements

Microsoft is retiring the containerized SAP data connector by October 14, 2026, requiring customers to migrate to the supported agentless SAP data connector to ensure continued SAP log ingestion in Microsoft Sentinel.

- The containerized SAP data connector was retired on September 14, 2026, and container images will be removed on October 14, 2026, disabling new pulls and deployments.
- Customers must migrate to the agentless SAP data connector, which offers simplified deployment, reduced maintenance, and a future-proof architecture based on SAP Integration Suite and SAP Cloud Connector.
- Migration involves running the agentless connector alongside the containerized agent, validating log ingestion, and then decommissioning the containerized agent to maintain uninterrupted SAP log collection.
- Existing analytics rules, workbooks, and playbooks remain functional with the agentless connector, which provides feature parity and supports extensions without changes to existing content.

Documentation: [Migrate to the Microsoft Sentinel agentless SAP data connector](https://learn.microsoft.com/en-us/azure/sentinel/sap/sap-agent-migrate)
