### [Public Preview: Network egress controls for hosted agents in Microsoft Foundry](https://azure.microsoft.com/en-us/updates?id=571821)

**Status:** In preview | **Published:** 2026-09-18 | **Products:** Microsoft Foundry | **Tags:** Feature

Microsoft Foundry introduces public preview of network egress controls for hosted agents, enabling customers to govern outbound connections with flexible, policy-based rules enforced within the agent sandbox, enhancing security and compliance without extra network appliances.

- Customers can create ordered rules based on destination hosts (including wildcard FQDNs) to allow, deny, transform headers, or rewrite destinations for outbound agent traffic.
- Rules are enforced inside the Foundry-managed agent sandbox before traffic leaves, eliminating the need for separate network appliances for basic allow-listing.
- Two enforcement modes are available: audit (logs would-be denied traffic) and enforce (blocks denied traffic), with all decisions logged to Application Insights for auditing.
- The feature is in public preview for evaluation, not covered by production SLAs, and configured via the Guardrails section in the Foundry portal.

Documentation: [Microsoft Foundry documentation](https://learn.microsoft.com/en-us/azure/foundry/)
