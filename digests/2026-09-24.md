### [Retirement: Support for PowerShell 7.4 ends on November 10, 2026](https://azure.microsoft.com/en-us/updates?id=572770)

**Status:** Retirement | **Published:** 2026-09-23 | **Products:** Azure Functions | **Tags:** Retirements, Compliance, Security

Support for PowerShell 7.4 in Azure Functions will end on November 10, 2026, requiring customers to upgrade to PowerShell 7.6 to maintain security, support, and performance.

- PowerShell 7.4 support and security updates end on November 10, 2026; customers must upgrade to PowerShell 7.6.
- Azure Function apps running on PowerShell 7.4 will continue to run but without security patches or customer support, risking vulnerabilities and degraded performance.
- Linux Consumption plan users must first upgrade to Flex Consumption plan before moving to PowerShell 7.6.
- Updating requires verifying extension bundles, binding extensions, package dependencies, local tools, and testing the function app locally; migration from in-process to isolated worker model is mandatory before the deadline.

Documentation: [Update Language Versions in Azure Functions](https://learn.microsoft.com/en-us/azure/azure-functions/update-language-versions?tabs=azure-portal%2Cwindows&pivots=programming-language-powershell)

### [Retirement: Support for .NET 8 and .NET 9 ends on November 10, 2026—upgrade your apps to .NET 10](https://azure.microsoft.com/en-us/updates?id=572838)

**Status:** Retirement | **Published:** 2026-09-23 | **Products:** Azure Functions | **Tags:** Retirements, Compliance, Security

Support for .NET 8 and .NET 9 in Azure Functions ends on November 10, 2026, requiring customers to upgrade to .NET 10 to maintain security, performance, and support.

- After November 10, 2026, Azure Functions running on .NET 8 or .NET 9 will no longer receive security updates, new features, or performance optimizations.
- Apps using unsupported .NET versions may face security vulnerabilities, performance degradation, and limited scaling capabilities.
- Customers must migrate in-process model apps to the isolated worker model before upgrading to .NET 10; isolated worker model apps can upgrade directly.
- Linux Consumption plan users must upgrade to the Flex Consumption plan before moving to .NET 10.

Documentation: [Azure Functions language stack support policy](https://learn.microsoft.com/en-us/azure/azure-functions/language-support-policy)
