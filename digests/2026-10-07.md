### [Retirement: Pod name dimension in AKS pod platform metrics](https://azure.microsoft.com/en-us/updates?id=570232)

**Status:** Retirement | **Published:** 2026-10-06 | **Products:** Azure Kubernetes Service (AKS) | **Tags:** Retirements

Azure Monitor is retiring the pod name dimension in AKS pod platform metrics by September 30, 2027, transitioning to aggregate pod counters to simplify monitoring and improve scalability.

- The pod name dimension will no longer be available for filtering, grouping, or alerting on kube_pod_status_phase and kube_pod_status_ready metrics after September 30, 2027.
- Metric names and aggregate pod counts remain unchanged, preserving namespace-level monitoring scenarios.
- During the deprecation period, both existing pod name dimension and new aggregate implementations will be supported with at least one year of historical data.
- Customers using pod name dimension in dashboards, alerts, or automation should update their monitoring workflows before the retirement date; pod-level monitoring is recommended via Azure Monitor Managed Prometheus and Kubernetes-native pod metrics.

Documentation: [Monitoring data reference for Azure Kubernetes Service - Azure Kubernetes Service](https://learn.microsoft.com/en-us/azure/aks/monitor-aks-reference)

### [Retirement: Azure App Service on Azure Stack Hub](https://azure.microsoft.com/en-us/updates?id=568178)

**Status:** Retirement | **Published:** 2026-10-06 | **Products:** App Service, Azure Stack Hub | **Tags:** Retirements

Azure App Service on Azure Stack Hub will be retired by September 30, 2029, requiring customers to migrate to Azure App Service in Azure to benefit from ongoing support, security updates, and new features.

- New installations of Azure App Service on Azure Stack Hub will not be supported after September 30, 2026, with full retirement and end of support on September 30, 2029.
- Azure App Service in Azure offers a fully managed, globally available platform with advanced features like autoscaling, deployment slots, and enhanced networking and security.
- Migration enables access to continuous platform innovations, higher-capacity Premium plans, and support for mixed Windows and Linux workloads with lower operational overhead.
- Customers should inventory applications, assess compatibility, and complete migration before retirement to maintain support and leverage improved scalability and security.

Documentation: [Benefits of Migrating to Azure App Service in Azure - Azure Stack Hub](https://learn.microsoft.com/en-us/azure-stack/operator/app-service-benefits-migrate-to-azure?view=azs-2604)

### [Retirement: Support for Java 8, 11 and 17 will end on September 1, 2027](https://azure.microsoft.com/en-us/updates?id=568585)

**Status:** Retirement | **Published:** 2026-10-06 | **Products:** App Service | **Tags:** Retirements

Support for Java 8, 11, and 17 on Azure App Service will end on September 1, 2027, requiring customers to upgrade to Java 25 to maintain security updates and support.

- Support and security updates for Java 8, 11, and 17 will cease after September 1, 2027, though apps will continue to run.
- Customers must upgrade their App Service apps to Java 25 before the deadline to avoid security vulnerabilities and loss of customer service.
- Azure App Service provides Microsoft and Adoptium OpenJDK builds for Java versions 8, 11, 17, 21, and 25 with quarterly security patches for supported versions.
- Deprecation notices are given at least six months in advance to help developers plan upgrades and maintain secure, supported environments.

Documentation: [Language Runtime Support Policy - Azure App Service](https://learn.microsoft.com/en-us/azure/app-service/language-support-policy)

## Databases

### [Retirement: Always Encrypted with Intel SGX Enclaves](https://azure.microsoft.com/en-us/updates?id=569236)

**Status:** Retirement | **Published:** 2026-10-06 | **Products:** Azure SQL Database | **Tags:** Retirements

Azure SQL Database is retiring Always Encrypted with Intel SGX enclaves by October 31, 2027, due to phasing out SGX-enabled DC-series hardware, urging customers to migrate to hardware-independent VBS enclaves or Confidential VMs for continued enclave functionality.

- Always Encrypted with Intel SGX enclaves support ends on October 31, 2027, as DC-series hardware is phased out.
- Customers must migrate workloads from DC-series to supported Standard-series compute tiers to maintain enclave features.
- Virtualization-Based Security (VBS) enclaves offer a hardware-independent alternative with no attestation required.
- Client drivers and connection strings need updating to support VBS enclaves and remove SGX attestation parameters.
