## Networking

### [Public Preview: Disable VNet peering route](https://azure.microsoft.com/en-us/updates?id=576242)

**Status:** In preview | **Published:** 2026-10-20 | **Products:** Virtual Network | **Tags:** Features, Management, Services

Azure announced the public preview of the disable VNet peering route feature, enabling more granular control over traffic routing between peered virtual networks to simplify route management in large hub-and-spoke architectures.

- Disable VNet peering route (DPR) suppresses system-generated peering routes on subnets linked to a route table while keeping the peering connection intact.
- Ideal for large hub-and-spoke networks, allowing traffic to be directed through network virtual appliances like Azure Firewall using summarized user-defined routes.
- DPR is managed via route-table configurations or Azure Virtual Network Manager routing rule collections; it requires manual configuration of replacement UDRs and inspection paths.
- This feature helps reduce complexity in route management as networks scale, improving traffic control without disrupting existing peering connections.

Documentation: [Azure Virtual Network Peering](https://learn.microsoft.com/en-us/azure/virtual-network/virtual-network-peering-overview?branch=main#disable-peering-route-propagation-preview)

### [Generally Available: Service tag match condition for Azure Front Door Premium WAF](https://azure.microsoft.com/en-us/updates?id=577156)

**Status:** Launched | **Published:** 2026-10-20 | **Products:** Azure Front Door, Web Application Firewall | **Tags:** Features

Azure Front Door Premium WAF now generally supports service tag match conditions in custom rules, enabling easier and more precise control of traffic from Azure services without managing IP lists.

- Service tag match condition allows custom WAF rules to match HTTP request source IPs against Azure service tags, which are automatically updated IP address groups.
- Supports use cases like allowing trusted Azure services, blocking unexpected Azure service traffic, restricting sensitive paths, and rate limiting service traffic.
- Available in Azure Front Door Premium WAF with match variables SocketAddr (recommended) and RemoteAddr, selectable service tags, and no wildcard support.
- Improves security and operational efficiency by simplifying rule management and enabling fine-grained traffic control based on Azure service origin.

Documentation: [Service Tag Match Condition for Azure Front Door - Azure Web Application Firewall](https://learn.microsoft.com/en-us/azure/web-application-firewall/afds/service-tag-match-condition)

### [Generally Available: Keyless TLS on Application Gateway with Azure Key Vault Managed HSM](https://azure.microsoft.com/en-us/updates?id=577130)

**Status:** Launched | **Published:** 2026-10-20 | **Products:** Application Gateway | **Tags:** Features

Azure Application Gateway now supports keyless TLS termination using Azure Key Vault Managed HSM, ensuring private keys remain secure within FIPS 140-3 Level 3 validated HSMs and enhancing security and compliance for TLS operations.

- TLS handshake signatures are performed inside Azure Key Vault Managed HSM, with private keys never exported to the gateway.
- Supports private key custody, managed identities, RBAC, and monitoring through Managed HSM diagnostic logs.
- Enables separation of duties and centralized key management with cryptographic evidence of key generation and storage.
- Leverages Azure Key Vault Managed HSM's high availability, single-tenant isolation, and FIPS 140-3 Level 3 validation for enhanced security and compliance.

Documentation: [Azure Key Vault Managed HSM Overview - Azure Key Vault Managed HSM](https://learn.microsoft.com/en-us/azure/key-vault/managed-hsm/overview)
