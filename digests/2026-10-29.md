## Management and governance

### [Public Preview: Cross Tenant Restore with Azure Backup](https://azure.microsoft.com/en-us/updates?id=577117)

**Status:** In preview | **Published:** 2026-10-28 | **Products:** Azure Backup | **Tags:** Management, Microsoft Ignite, Security, Feature

Azure Backup now supports Cross-Tenant Restore in public preview, enabling organizations to restore Azure VM backups into a different Azure tenant to enhance cyber resilience without duplicating backup data.

- Capability: Restore Azure VMs from backup recovery points into separate Azure tenants using the Azure portal or Resiliency experience.
- Scope: Supports restoring managed disks <4 TB or VMs with <16 disks from Vault-Standard recovery points, including legacy unmanaged disk backups.
- Storage requirements: Storage accounts must be in the same region as the vault; Blob Storage accounts are unsupported; Zone redundant storage (ZRS) is supported.
- Customer impact: Enables independent recovery paths across tenants, strengthening cyber resilience while avoiding the cost and complexity of maintaining duplicate backups.

Documentation: [Restore VMs by using the Azure portal using Azure Backup - Azure Backup](https://learn.microsoft.com/en-us/azure/backup/backup-azure-arm-restore-vms)

## Containers

### [Announcing: Migrate Azure Container Apps logging destination from Log Analytics to Azure Monitor](https://azure.microsoft.com/en-us/updates?id=577689)

**Status:** Effective | **Published:** 2026-10-28 | **Products:** Azure Container Apps | **Tags:** Announcement

Azure Container Apps is deprecating the Log Analytics logging destination in favor of Azure Monitor due to the legacy HTTP Data Collector API reaching end of support, requiring customers to migrate for continued secure log ingestion.

- Log Analytics logging destination for Azure Container Apps is now legacy; existing setups continue to work but migration to Azure Monitor is recommended.
- The legacy HTTP Data Collector API support ends on September 14, 2026, with only critical security updates thereafter.
- Migration involves switching to the Logs ingestion API, which supports schema management, RBAC, and OAuth-based authentication via Microsoft Entra.
- Customers must review and update monitoring resources (queries, dashboards, alerts, workbooks) that depend on legacy tables ContainerAppConsoleLogs_CL and ContainerAppSystemLogs_CL.

Documentation: [Migrate From the HTTP Data Collector API to the Logs Ingestion API - Azure Monitor](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/custom-logs-migrate?tabs=cli)
