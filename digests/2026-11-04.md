### [Public Preview: JWT validation for Application Gateway for Containers](https://azure.microsoft.com/en-us/updates?id=576382)

**Status:** In preview | **Published:** 2026-11-03 | **Products:** Application Gateway | **Tags:** Features

Application Gateway for Containers now supports centralized JWT validation via AuthPolicy, enabling secure token verification at the gateway to protect backend services and improve security.

- Supports JWT validation for HTTP, gRPC, and MCP routes using AuthPolicy Kubernetes custom resource.
- Validates token signature, issuer, lifetime, and audience with signing keys from trusted HTTPS JWKS endpoints.
- Rejects requests with missing or invalid tokens at the gateway, preventing unauthorized backend access.
- Integrates with Microsoft Entra ID and third-party identity providers, and complements Web Application Firewall (WAF) for layered security.

Documentation: [JWT validation for Application Gateway for Containers](https://learn.microsoft.com/en-us/azure/application-gateway/for-containers/jwt-validation)

**Status:** In preview | **Published:** 2026-11-03 | **Products:** Application Gateway | **Tags:** Features

Application Gateway for Containers now supports Model Context Protocol (MCP) routing via the new MCPRoute custom resource, enabling centralized, secure, and scalable access to multiple MCP servers through a single gateway endpoint.

### [Public Preview: Private ingress for Application Gateway for Containers](https://azure.microsoft.com/en-us/updates?id=576393)

**Status:** In preview | **Published:** 2026-11-03 | **Products:** Application Gateway | **Tags:** Features

Application Gateway for Containers now supports private ingress via Azure Private Link private endpoints, enabling secure, private connectivity for Kubernetes workloads across VNets, subscriptions, tenants, and regions without VNet peering, enhancing security and network architecture flexibility.

- Supports private frontends accessible only through explicitly provisioned Azure Private Link private endpoints, removing public internet exposure.
- Enables cross-boundary private connectivity across VNets, subscriptions, Microsoft Entra tenants, and Azure regions, including overlapping CIDR ranges, without requiring VNet peering.
- Allows hosting of both public and private frontends on a single Application Gateway for Containers resource, enabling different exposure models and security policies per workload.
- Facilitates architectures with upstream firewalls or network virtual appliances for centralized traffic inspection, while preserving Kubernetes-native Layer 7 routing, TLS, health probing, and WAF capabilities.

Documentation: [Private ingress with Application Gateway for Containers](https://learn.microsoft.com/en-us/azure/application-gateway/for-containers/private-ingress)

## Databases

### [Public Preview: Extend immutability for PITR backups for Azure SQL Database and Azure SQL Managed Instance](https://azure.microsoft.com/en-us/updates?id=579305)

**Status:** In preview | **Published:** 2026-11-03 | **Products:** Azure SQL Database, Azure SQL Managed Instance | **Tags:** Feature

Azure SQL Database and Managed Instance now support permanently locking backup immutability to the configured PITR retention period beyond the default 7 days, enhancing data protection especially for customers with longer retention needs.

- Capability to lock immutability to the full configured PITR retention period, up to 35 days, beyond the default 7 days.
- Locking immutability is permanent and only allows increasing, not decreasing, the PITR retention period for the database.
- Immutability protection continues even if the database is deleted, ensuring retained backups remain immutable.
- Integrated into managed backup service without requiring additional storage account or policy management, simplifying backup protection.

Documentation: [Automatic backup immutability for Azure SQL Database and Azure SQL Managed Instance - Azure SQL](https://learn.microsoft.com/en-us/azure/azure-sql/automatic-backup-immutability?view=azuresql)

## Management and governance

### [Generally Available: Enhanced Azure Site Recovery support for VMSS Flex](https://azure.microsoft.com/en-us/updates?id=578926)

**Status:** Launched | **Published:** 2026-11-03 | **Products:** Azure Site Recovery | **Tags:** Feature

Azure Site Recovery now generally supports enhanced disaster recovery for VMs in Virtual Machine Scale Sets with flexible orchestration, improving failover, reprotection, and failback workflows to ensure better resilience and recovery management.

- Supports individual VM replication within VMSS Flex, requiring manual selection of VMs for protection and recovery plans for group failover.
- Target scale sets must be pre-created and configured; scale set configuration and autoscale settings are not replicated automatically.
- Failover places recovery VMs in the configured availability zone and fault domain; reprotect and failback restore workloads to original VMSS Flex configurations.
- New VMs added post-replication enablement are not automatically protected; capacity reservations and proximity placement groups have specific limitations.

Documentation: [Enable disaster recovery for VMs in Virtual Machine Scale Sets with Flexible orchestration - Azure Site Recovery](https://learn.microsoft.com/en-us/azure/site-recovery/azure-to-azure-how-to-enable-replication-vmss-flex)
