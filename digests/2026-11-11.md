### [Public Preview: Azure Front Door adds native gRPC support](https://azure.microsoft.com/en-us/updates?id=579383)

**Status:** In preview | **Published:** 2026-11-10 | **Products:** Azure Front Door | **Tags:** Features, Services

Azure Front Door now supports native gRPC routing in public preview, enabling secure, efficient, and health-aware delivery of gRPC applications over HTTP/2 and HTTPS.

- Supports routing gRPC calls to specific services and methods with load balancing across healthy origins using Azure Front Door Standard and Premium.
- Enables unary and streaming RPCs with full HTTP/2 and HTTPS support from client to origin, including native gRPC health probes for traffic distribution.
- Supports Azure Front Door security and routing features such as rule sets and Edge Actions on gRPC-enabled routes, requiring HTTPS forwarding.
- Requires gRPC-enabled origins with TLS and HTTP/2, configuration of origin groups and health probes, and supports testing via grpcurl and .proto files.

Documentation: [gRPC support in Azure Front Door (preview)](https://learn.microsoft.com/en-us/azure/frontdoor/grpc)

### [Generally Available: Azure Front Door edge actions](https://azure.microsoft.com/en-us/updates?id=579310)

**Status:** Launched | **Published:** 2026-11-10 | **Products:** Azure Front Door | **Tags:** Features, Services

Azure Front Door edge actions are now generally available, enabling customers to run lightweight JavaScript functions at the edge for improved performance, security, and application flexibility.

- Edge actions allow execution of custom JavaScript during client request/response processing at Azure Front Door edge locations.
- Built on secure Hyperlight micro-VM technology, providing hardware-backed isolation for code execution.
- Supports scenarios like A/B testing, canary deployments, header manipulation, request filtering, dynamic origin selection, and edge authentication.
- Edge actions integrate with Azure Front Door features such as rules engine, caching, routing, and Web Application Firewall (WAF).

Documentation: [Edge Actions - Azure Front Door](https://learn.microsoft.com/en-us/azure/frontdoor/edge-actions)

### [Public Preview: Azure Route Server dual-stack IPv4/IPv6 support](https://azure.microsoft.com/en-us/updates?id=579746)

**Status:** Effective | **Published:** 2026-11-10 | **Products:** Azure Route Server | **Tags:** Features

Azure Route Server now supports IPv4/IPv6 dual-stack mode in public preview, allowing simultaneous route exchange for both protocols to enhance hybrid network architectures.

- Supports dual-stack IPv4/IPv6 routing for ExpressRoute, VPN Gateway, and network virtual appliance connections in hub or spoke virtual networks.
- Existing IPv4-only connections remain unchanged, enabling gradual adoption of IPv6 without disrupting current connectivity.
- Dual-stack mode is enabled via the Azure portal by adding an IPv6 /64 prefix to the RouteServerSubnet; the change is irreversible and may take up to 40 minutes to complete.
- Customers must resync hub-and-spoke virtual network peerings after enabling IPv6 to maintain correct configurations and verify provisioning status before proceeding.

Documentation: [Enable IPv4/IPv6 dual-stack mode on Azure Route Server](https://learn.microsoft.com/en-us/azure/route-server/enable-route-server-dual-stack)

### [Generally Available: Azure Functions support for .NET 11](https://azure.microsoft.com/en-us/updates?id=578773)

**Status:** Launched | **Published:** 2026-11-10 | **Products:** Azure Functions | **Tags:** Features, SDK and Tools, Feature

Azure Functions now generally supports building apps targeting .NET 11 using the isolated worker model, enabling improved runtime performance and enhanced developer capabilities.

- Supports .NET 11 with the isolated worker model while maintaining Azure Functions programming model and host integration.
- Benefits include runtime performance optimizations, richer APIs, enhanced tooling, fewer assembly conflicts, and full control over app startup and dependency injection.
- Requires Azure.Functions.Sdk version 1.0.1+ and explicit Microsoft.Azure.Functions.Worker package; currently supports C# only, with F# support temporarily unavailable.
- Linux Consumption plan does not support .NET 10+ apps; use Flex Consumption plan for Linux deployments targeting .NET 11.

Documentation: [Guide for running C# Azure Functions in an isolated worker process](https://learn.microsoft.com/en-us/azure/azure-functions/dotnet-isolated-process-guide)

## Containers

### [Public Preview: Distributed accelerator for cloud storage on AKS](https://azure.microsoft.com/en-us/updates?id=578454)

**Status:** In preview | **Published:** 2026-11-10 | **Products:** Azure Container Storage | **Tags:** Feature

Distributed accelerator for cloud storage (DACS) is now in public preview on AKS, providing a distributed NVMe cache to speed up AI model loading and dataset reads by reducing repeated Azure Blob Storage access.

- DACS runs within AKS clusters using local NVMe disks to cache frequently read data from Azure Blob Storage, improving inference and training workload performance.
- Supports up to 100-node Linux AKS clusters with dedicated NVMe cache nodes; cache servers distribute model data chunks without centralized dependency.
- Enables faster warm-model loading, quicker scale-out and recovery by reusing cached data, and reduces repeated Blob Storage reads, benefiting AI workloads at scale.
- Integrates with workloads via Azure Container Storage, Run:ai Model Streamer, BlobFuse2, or native Python client, with Azure Blob Storage as fallback and durable source of truth.

Documentation: [What is distributed accelerator for cloud storage? (preview) - Azure Storage](https://learn.microsoft.com/en-us/azure/storage/container-storage/distributed-accelerator-for-cloud-storage-overview)
