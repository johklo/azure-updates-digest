### [Public Preview: JWT validation with Azure Front Door Auth Policy](https://azure.microsoft.com/en-us/updates?id=577673)

**Status:** In preview | **Published:** 2026-11-12 | **Products:** Azure Front Door | **Tags:** Features, Security

Azure Front Door Premium now publicly previews JWT validation via Auth Policy to authenticate Microsoft Entra ID bearer tokens at the edge, enhancing security and reducing origin load.

- JWT validation supports tokens issued by Microsoft Entra ID, verifying signature, expiration, issuer, and audience before forwarding requests.
- Authentication policies can be associated at profile, domain, or route scope with precedence Route > Domain > Profile.
- Supports Block mode to reject invalid tokens with HTTP 401 and Log mode to evaluate without blocking.
- Allows configuration of token header location and optional forwarding of validated tokens to origins, requiring secure origin access to prevent bypass.

Documentation: [Validate JSON Web Tokens with an authentication policy (Preview) - Azure Front Door](https://learn.microsoft.com/en-us/azure/frontdoor/authentication-policy)

### [Generally Available: Azure Front Door mutual TLS authentication](https://azure.microsoft.com/en-us/updates?id=577678)

**Status:** Launched | **Published:** 2026-11-12 | **Products:** Azure Front Door | **Tags:** Features, Security

Azure Front Door Premium now generally supports mutual TLS (mTLS) authentication with flexible modes and simplified trusted CA configuration, enhancing secure client authentication for sensitive applications.

- Supports four mTLS modes: require and validate, require without validation, validate if presented, and passthrough to origin, allowing flexible client certificate enforcement and validation locations.
- Simplifies trusted CA setup by requiring only the trusted root CA certificate upload to Azure Key Vault; Azure Front Door builds and validates the full client certificate chain at request time.
- Validates client certificates for date validity, Extended Key Usage, SAN/CN against allowed list, and revocation status via OCSP, responding with HTTP 403 if revoked.
- Supports both public and private CA-issued certificates but recommends transitioning to private CAs for client authentication due to industry changes affecting public CA EKU issuance.

Documentation: [Mutual TLS authentication - Azure Front Door](https://learn.microsoft.com/en-us/azure/frontdoor/mutual-tls)

### [Public Preview: Auto scaling of ingestion limits in Azure Monitor workspace](https://azure.microsoft.com/en-us/updates?id=578207)

**Status:** In preview | **Published:** 2026-11-12 | **Products:** Azure Kubernetes Service (AKS), Azure Monitor | **Tags:** Feature

Azure Monitor Workspace now supports auto scaling of ingestion limits to dynamically adjust quotas based on usage, reducing manual management and preventing throttling.

- Auto scaling is an opt-in feature that automatically raises or lowers ingestion limits per workspace based on observed metrics volume and utilization.
- This capability eliminates the need for manual support requests to increase limits and avoids over-provisioning by aligning limits with actual usage.
- Users can monitor ingestion utilization via Azure Monitor workspace metrics and receive alerts on scale changes through recommended alert rules and activity logs.
- The feature is available via Azure CLI, ARM templates, and Bicep deployments, enabling easy enablement and integration into existing workflows.

Documentation: [Monitor Azure Monitor workspace metrics ingestion - Azure Monitor](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/azure-monitor-workspace-monitor-ingest-limits)
