**Status:** Launched | **Published:** 2026-11-17 | **Products:** Azure HorizonDB | **Tags:** Microsoft Ignite, Feature

Azure HorizonDB now supports geo-redundant backup and restore, enabling cross-region recovery to enhance business continuity and disaster recovery.

- Geo-redundant backup replicates backup data and WAL records asynchronously to a paired Azure region, providing an additional recovery option.
- This feature must be enabled at cluster creation and supports restoring the cluster to its paired region, with an RPO of up to one hour due to asynchronous replication.

- Geo-redundant backups improve disaster recovery preparedness but cannot be combined with customer-managed keys currently.

### [Generally Available: Throughput buckets in Azure Cosmos DB](https://azure.microsoft.com/en-us/updates?id=571488)

**Status:** Launched | **Published:** 2026-11-17 | **Products:** Azure Cosmos DB | **Tags:** Microsoft Ignite, Feature

Azure Cosmos DB now generally supports throughput buckets, enabling customers to limit maximum throughput per workload within a shared container to prevent resource contention and improve workload management.

- Throughput buckets allow capping the maximum throughput a workload can consume as a percentage of a container's total throughput, without reserving throughput exclusively.
- Supports scenarios like multitenant ISV workloads, ETL bulk jobs, data ingestion, and change feed processing by preventing any single workload from monopolizing resources.
- Up to five throughput buckets can be configured per container via Azure portal Data Explorer, with optional default bucket assignment for unassigned requests.
- SDKs support assigning requests or clients to specific throughput buckets; monitoring metrics are available by throughput bucket, but this feature is not supported for containers in Shared Throughput Databases.
