**Status:** In preview | **Published:** 2026-11-24 | **Products:** Microsoft Foundry | **Tags:** Features, Microsoft Ignite

Foundry Agent Service now offers public preview of optimization from insights, enabling users to generate and evaluate candidate changes to prompt agents for improved performance, with separate workflows for prompt and hosted agents.

**Status:** In preview | **Published:** 2026-11-24 | **Products:** Microsoft Foundry | **Tags:** Features, Microsoft Ignite

Microsoft Foundry Agent Service now supports routing MCP tool traffic through customer-managed AI Gateway or Azure API Management endpoints, enabling centralized control and governance of MCP tools.

### [Public Preview: Native A2A passthrough for hosted agents in Foundry Agent Service](https://azure.microsoft.com/en-us/updates?id=581313)

**Status:** In preview | **Published:** 2026-11-24 | **Products:** Microsoft Foundry | **Tags:** Features, Microsoft Ignite

Azure Foundry Agent Service now supports native Agent2Agent (A2A) passthrough in public preview, enabling direct forwarding of A2A requests to hosted agents without protocol conversion, simplifying integration and improving performance.

- Supports native A2A v1.0 requests over JSON-RPC, bypassing previous protocol conversion to Responses protocol.
- Agent Service manages endpoint, authentication, and hosted compute while forwarding requests directly to hosted agent containers.
- Currently in public preview with limitations: no support for streaming, push notifications, or authenticated extended agent cards.
- Focuses on handling incoming A2A requests; outbound calls to other agents are not configured by this feature.

Documentation: [Microsoft documentation](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/host-agent-to-agent-server)

**Status:** In preview | **Published:** 2026-11-24 | **Products:** Microsoft Foundry | **Tags:** Features, Microsoft Ignite

### [Public Preview: Central governance of hosted-agent outbound domains in Foundry Agent Service](https://azure.microsoft.com/en-us/updates?id=581328)

**Status:** In preview | **Published:** 2026-11-24 | **Products:** Microsoft Foundry | **Tags:** Features, Microsoft Ignite

Azure Policy now enables central governance of outbound domains for hosted agents in Foundry Agent Service, allowing administrators to enforce compliant egress policies at runtime and improve security and compliance management.

- Administrators can use Azure Policy to audit or deny noncompliant outbound egress configurations for hosted agents before agent version creation.
- Governance requires assigning specific control-plane and data-plane policy definitions with appropriate permissions and scope, impacting runtime outbound requests.
- Policy assignment changes take 30-60 minutes to propagate, and compliance reporting is asynchronous, so immediate enforcement or revocation of running sessions is not guaranteed.
- This capability helps enterprises centrally enforce network egress controls for hosted agents, enhancing security posture without disrupting existing sessions.

Documentation: [Govern Microsoft Foundry hosted agent egress with Azure Policy (preview) - Microsoft Foundry](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/govern-hosted-agent-egress-azure-policy)
